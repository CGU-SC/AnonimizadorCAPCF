A mudança

abrir/abrir-dev.bat
O atalho de abrir o programa só instalava as dependências quando criava a pasta do ambiente virtual pela primeira vez. Se essa instalação fosse interrompida no meio — internet caindo, janela fechada —, a pasta ficava de pé mas incompleta, e o atalho pulava a instalação para sempre: a pessoa clicava, o programa não abria, e não havia nada que ela pudesse fazer sozinha para sair desse estado. Agora a conferência das dependências roda toda vez. Estando tudo instalado, ela leva pouco mais de um segundo e nada muda no que se vê.
Antes
if not exist ".venv\Scripts\python.exe" (
    echo   Ambiente virtual nao encontrado - criando...
    python -m venv .venv
    if errorlevel 1 goto erro
    echo   Instalando as dependencias, pode levar um minuto...
    ".venv\Scripts\python.exe" -m pip install -r requirements.txt
    if errorlevel 1 goto erro
)
Depois
if not exist ".venv\Scripts\python.exe" (
    echo   Ambiente virtual nao encontrado - criando...
    python -m venv .venv
    if errorlevel 1 goto erro
)

REM A instalacao roda sempre, e nao so quando o ambiente e
REM criado: uma instalacao interrompida no meio deixa a pasta
REM .venv de pe mas incompleta, e quem so clica no atalho
REM ficaria preso nesse estado para sempre. Estando tudo
REM instalado, este passo confere e sai em poucos segundos.
echo   Conferindo as dependencias, pode levar um minuto na primeira vez...
".venv\Scripts\python.exe" -m pip install -r requirements.txt

O que foi achado e NÃO consertado

O fundo escuro do menu lateral não está sendo pintado

Medido rodando a janela sem tela: a faixa do menu sai #efefef (o cinza-claro padrão do Windows), com o texto cinza #9aa1ac por cima; o escuro #262b33 aparece só atrás do nome do programa. Fica diferente do rascunho aprovado (mockups/janela/01-interface-da-janela.html) e o contraste do texto piora.

Por que não foi consertado: é defeito visual, e não cabe em nenhuma das quatro classes da lente crítica desta rodada — quem o veria é a lente CONFERIR NA TELA, que ainda não rodou. A decisão de abrir essa rodada é de quem usa o programa.
Esta página mostra o que foi mexido — não que o programa continua funcionando. Isso quem mostrou foi você: depois do conserto, rodou o atalho e confirmou que o programa abriu, com o passo novo de conferência das dependências passando sem erro.
